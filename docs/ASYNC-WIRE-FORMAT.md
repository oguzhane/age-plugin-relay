# Async Wire Format Reference

Complete HTTP request/response bodies for the async flow. All interactions use `POST` with `Content-Type: application/json`. Every request body is a `RelayRequest` (same Go struct, different fields populated per action).

Three actors: **Plugin**, **Broker**, **Operator**.

---

## 1. Plugin → Broker: submit intent

**Action:** `unwrap`

### Request

```json
{
  "version": 1,
  "action": "unwrap",
  "intent_id": "a3f12c4e8b9d6f0a1b2c3d4e5f6a7b8c",
  "tag": "QPg24ggKk7xKd2t3c5rL9A",
  "expires_at": 1715350800,
  "intent_claim_pub": "<base64: Ed25519 public key>",
  "encrypted_payload": "<base64: age-encrypted InnerRequestPayload>"
}
```

| Field | Type | Description |
|---|---|---|
| `version` | int | Always `1` |
| `action` | string | `"unwrap"` |
| `intent_id` | string | 16 random bytes, hex-encoded (32 chars). Generated by plugin |
| `tag` | string | `base64(SHA-256(unwrap_recipient)[:16])`. Routing tag for operator pull |
| `expires_at` | int64 | Unix timestamp (seconds). Plugin sets `now + timeout` |
| `intent_claim_pub` | string | Ed25519 public key (base64 raw standard, 44 chars). Per-intent authorization — see [Intent Claim](INTENT-CLAIM.md) |
| `encrypted_payload` | string | Base64 age ciphertext. Encrypted to operator's recipient. Opaque to broker |

#### Inside `encrypted_payload` (decrypted by operator only)

```json
{
  "nonce": "deadbeef01020304deadbeef01020304",
  "outer_hash": "<SHA-256 hex, 64 chars>",
  "expires_at": 1715350800,
  "stanzas": [
    {
      "type": "X25519",
      "args": ["ephemeral-share"],
      "body": "<base64 raw std>"
    }
  ],
  "ephemeral_key": "age1qqnv7...plugin's ephemeral public key...",
  "intent_claim_secret": "<base64: Ed25519 private key seed>"
}
```

`outer_hash` covers every envelope field outside `encrypted_payload` (the [Complete Outer Field Binding](ARCHITECTURE.md#35-outer-hash-construction) principle):

`outer_hash` = `SHA-256("1.unwrap.a3f12c4e8b9d6f0a1b2c3d4e5f6a7b8c.QPg24ggKk7xKd2t3c5rL9A.1715350800.<intent_claim_pub>")`

### Response — 202 Accepted

```json
{}
```

### Response — 409 Conflict (duplicate intent_id)

```json
{
  "error": "duplicate_intent"
}
```

### Response — 400 Bad Request (missing fields)

```json
{
  "error": "missing intent_id"
}
```

```json
{
  "error": "missing intent_claim_pub"
}
```

## 2. Operator → Broker: pull pending intents

**Action:** `pull`

### Request

```json
{
  "version": 1,
  "action": "pull",
  "tag": "QPg24ggKk7xKd2t3c5rL9A"
}
```

| Field | Type | Description |
|---|---|---|
| `version` | int | Always `1` |
| `action` | string | `"pull"` |
| `tag` | string | Operator filters by this tag |

### Response — 200 OK

```json
{
  "intents": [
    {
      "intent_id": "a3f12c4e8b9d6f0a1b2c3d4e5f6a7b8c",
      "request": {
        "version": 1,
        "action": "unwrap",
        "intent_id": "a3f12c4e8b9d6f0a1b2c3d4e5f6a7b8c",
        "tag": "QPg24ggKk7xKd2t3c5rL9A",
        "expires_at": 1715350800,
        "encrypted_payload": "<base64: age-encrypted InnerRequestPayload>"
      }
    }
  ]
}
```

The `request` field is the **verbatim original** plugin POST body delivered as raw JSON. The broker stores the raw bytes and passes them through without parsing or restructuring. The `intent_id` appears both at the top level (for convenience) and inside `request`.

If no pending intents match the tag:

```json
{
  "intents": []
}
```

## 3. Operator → Broker: fulfill

**Action:** `fulfill`

### Request

```json
{
  "version": 1,
  "action": "fulfill",
  "intent_id": "a3f12c4e8b9d6f0a1b2c3d4e5f6a7b8c",
  "intent_claim_sig": "<base64: Ed25519 signature>",
  "encrypted_payload": "<base64: age-encrypted InnerResponsePayload>"
}
```

| Field | Type | Description |
|---|---|---|
| `version` | int | Always `1` |
| `action` | string | `"fulfill"` |
| `intent_id` | string | The intent being fulfilled |
| `intent_claim_sig` | string | Ed25519 signature (base64 raw standard, 88 chars). Signs `"{version}.fulfill.{intent_id}.{SHA-256(encrypted_payload)}"` — see [Intent Claim](INTENT-CLAIM.md) |
| `encrypted_payload` | string | Base64 age ciphertext. Encrypted to plugin's ephemeral recipient. Opaque to broker |

#### Inside `encrypted_payload` (decrypted by plugin only)

```json
{
  "nonce": "1a2b3c4d5e6f7a8b1a2b3c4d5e6f7a8b",
  "outer_hash": "<SHA-256 hex, 64 chars>",
  "file_key": "<base64 raw std: 16-byte age file key>"
}
```

`outer_hash` covers every response envelope field outside `encrypted_payload`:

`outer_hash` = `SHA-256("1.fulfill.a3f12c4e8b9d6f0a1b2c3d4e5f6a7b8c")`

### Response — 200 OK

```json
{
  "status": "ok"
}
```

### Response — 404 Not Found

```json
{
  "error": "unknown_intent"
}
```

### Response — 409 Conflict

```json
{
  "error": "intent_already_terminal"
}
```

### Response — 403 Forbidden

```json
{
  "error": "invalid_claim_sig"
}
```

## 4. Operator → Broker: reject

**Action:** `reject`

### Request

```json
{
  "version": 1,
  "action": "reject",
  "intent_id": "a3f12c4e8b9d6f0a1b2c3d4e5f6a7b8c",
  "intent_claim_sig": "<base64: Ed25519 signature>",
  "encrypted_payload": "<base64: age-encrypted InnerResponsePayload with empty file_key>"
}
```

| Field | Type | Description |
|---|---|---|
| `version` | int | Always `1` |
| `action` | string | `"reject"` |
| `intent_id` | string | The intent being rejected |
| `intent_claim_sig` | string | Ed25519 signature (base64 raw standard). Signs `"{version}.reject.{intent_id}.{SHA-256(encrypted_payload)}"` — see [Intent Claim](INTENT-CLAIM.md) |
| `encrypted_payload` | string | Base64 age ciphertext. Encrypted to plugin's ephemeral recipient. Contains `InnerResponsePayload{nonce, outer_hash, file_key:""}` |

#### Inside `encrypted_payload` (decrypted by plugin only)

```json
{
  "nonce": "1a2b3c4d5e6f7a8b1a2b3c4d5e6f7a8b",
  "outer_hash": "<SHA-256 hex of '1.reject.a3f12c4e8b9d6f0a1b2c3d4e5f6a7b8c'>",
  "file_key": ""
}
```

The `outer_hash` covers every response envelope field outside `encrypted_payload`: `SHA-256("{version}.{action}.{intent_id}")`. The plugin decrypts and verifies this to confirm the reject is authentic (not forged by the broker).

### Response — 200 OK

```json
{
  "status": "ok"
}
```

### Response — 404 Not Found

```json
{
  "error": "unknown_intent"
}
```

### Response — 409 Conflict

```json
{
  "error": "intent_already_terminal"
}
```

### Response — 403 Forbidden

```json
{
  "error": "invalid_claim_sig"
}
```

## 5. Plugin → Broker: poll

**Action:** `poll`

### Request

```json
{
  "version": 1,
  "action": "poll",
  "intent_id": "a3f12c4e8b9d6f0a1b2c3d4e5f6a7b8c",
  "intent_claim_sig": "<base64: Ed25519 signature over '1.poll.{intent_id}.{SHA-256(\"\")}'>"
}
```

| Field | Type | Description |
|---|---|---|
| `version` | int | Always `1` |
| `action` | string | `"poll"` |
| `intent_id` | string | The intent to check |
| `intent_claim_sig` | string | **Required.** Ed25519 signature proving the caller is the intent creator. Canonical: `"{version}.poll.{intent_id}.{SHA-256("")}"` |

### Response — 400 Bad Request (missing sig)

```json
{"error": "missing intent_claim_sig"}
```

### Response — 403 Forbidden (invalid sig)

```json
{"error": "invalid_claim_sig"}
```

### Response — 200 OK (pending)

```json
{
  "status": "pending"
}
```

### Response — 200 OK (fulfilled)

```json
{
  "status": "fulfilled",
  "response": {
    "version": 1,
    "action": "fulfill",
    "intent_id": "a3f12c4e8b9d6f0a1b2c3d4e5f6a7b8c",
    "encrypted_payload": "<base64: age-encrypted InnerResponsePayload>"
  }
}
```

The `response` field is the **verbatim original** operator fulfill POST body delivered as raw JSON. The broker stores the raw bytes and passes them through without parsing or restructuring.

### Response — 200 OK (rejected)

```json
{
  "status": "rejected",
  "response": {
    "version": 1,
    "action": "reject",
    "intent_id": "a3f12c4e8b9d6f0a1b2c3d4e5f6a7b8c",
    "encrypted_payload": "<base64: age-encrypted InnerResponsePayload with empty file_key>"
  }
}
```

The `response` field is the **verbatim original** operator reject POST body delivered as raw JSON. The plugin decrypts `encrypted_payload` and verifies `outer_hash` to confirm the reject is authentic.

### Response — 404 Not Found (expired or unknown)

```json
{
  "error": "unknown_intent"
}
```

## Sync Flow Comparison

In the sync flow (relay-server, not broker), the plugin sends the same `unwrap` request structure directly to the relay-server. The relay-server decrypts, unwraps, and responds immediately with the same `RelayRequest` envelope shape:

### Sync response — 200 OK (JSON)

```json
{
  "version": 1,
  "action": "fulfill",
  "intent_id": "a3f12c4e8b9d6f0a1b2c3d4e5f6a7b8c",
  "encrypted_payload": "<base64: age-encrypted InnerResponsePayload>"
}
```

The response uses the same `RelayRequest` envelope as the async flow's operator fulfill body. Both sync and async responses use `action: "fulfill"` and the inner `outer_hash` is `SHA-256("{version}.fulfill.{intent_id}")`.

### Sync response — 200 OK (SSE)

```
: heartbeat

event: result
data: {"version":1,"action":"fulfill","intent_id":"a3f1...","encrypted_payload":"<age-encrypted blob>"}

```

### Sync error responses

```json
{
  "error": "description of error"
}
```

### Sync reject response — 200 OK (JSON)

```json
{
  "version": 1,
  "action": "reject",
  "intent_id": "a3f12c4e8b9d6f0a1b2c3d4e5f6a7b8c",
  "encrypted_payload": "<base64: age-encrypted InnerResponsePayload with empty file_key>"
}
```

### Sync reject response — 200 OK (SSE)

```
event: reject
data: {"version":1,"action":"reject","intent_id":"a3f1...","encrypted_payload":"<base64>"}

```

The sync reject response uses the same `RelayRequest` envelope shape as fulfill, with `action: "reject"` and an `encrypted_payload` containing `InnerResponsePayload{nonce, outer_hash, file_key:""}`. The plugin decrypts and verifies the outer hash `SHA-256("{version}.reject.{intent_id}")` to confirm authenticity.

## Go Types

All actors use the same `RelayRequest` struct for all actions (fields are `omitempty`):

```go
// relay/client.go
type RelayRequest struct {
    Version          int    `json:"version"`
    Action           string `json:"action"`
    IntentID         string `json:"intent_id,omitempty"`
    Tag              string `json:"tag,omitempty"`
    ExpiresAt        int64  `json:"expires_at,omitempty"`
    IntentClaimPub   string `json:"intent_claim_pub,omitempty"`
    IntentClaimSig   string `json:"intent_claim_sig,omitempty"`
    EncryptedPayload string `json:"encrypted_payload,omitempty"`
}
```

Broker response types:

```go
// relay/broker/types.go
type AsyncAccepted struct{}                          // 202 body: {}

type PullResponse struct {
    Intents []PullIntent `json:"intents"`
}

type PullIntent struct {
    IntentID string          `json:"intent_id"`
    Request  json.RawMessage `json:"request"`            // verbatim plugin POST body
}

type PollResponse struct {
    Status   string          `json:"status"`             // "pending" | "fulfilled" | "rejected"
    Response json.RawMessage `json:"response,omitempty"` // verbatim operator fulfill POST body
}
```

Plugin-side poll response (mirrors broker's `PollResponse` with an extra `error` field):

```go
// relay/client.go
type asyncPollResponse struct {
    Status   string          `json:"status"`
    Response json.RawMessage `json:"response,omitempty"`
    Error    string          `json:"error,omitempty"`
}
```

Sync response:

```go
// relay/client.go
type RelayResponse struct {
    EncryptedPayload string `json:"encrypted_payload,omitempty"`
    Error            string `json:"error,omitempty"`
}
```

Inner payloads (encrypted, opaque to broker):

```go
// relay/payload.go
type InnerRequestPayload struct {
    Nonce             string        `json:"nonce"`
    OuterHash         string        `json:"outer_hash"`
    ExpiresAt         int64         `json:"expires_at"`
    Stanzas           []RelayStanza `json:"stanzas"`
    EphemeralKey      string        `json:"ephemeral_key"`
    IntentClaimSecret string        `json:"intent_claim_secret,omitempty"`
}

type InnerResponsePayload struct {
    Nonce     string `json:"nonce"`
    OuterHash string `json:"outer_hash"`
    FileKey   string `json:"file_key"`
}

type RelayStanza struct {
    Type string   `json:"type"`
    Args []string `json:"args"`
    Body string   `json:"body"`
}
```

## Outer Hash Summary

> Every field in the cleartext envelope outside `encrypted_payload` MUST be included in the outer hash. See [ARCHITECTURE.md §3.5](ARCHITECTURE.md#35-outer-hash-construction).

> Every `action` value (fulfill, reject, etc.) MUST carry an `encrypted_payload` with an outer hash that the recipient verifies. No action is exempt. See [ARCHITECTURE.md §3.5](ARCHITECTURE.md#35-outer-hash-construction).

| Direction | Formula | Example |
|---|---|---|
| Request (plugin → server/operator) | `SHA-256("{version}.{action}.{intent_id}.{tag}.{expires_at}.{intent_claim_pub}")` | `SHA-256("1.unwrap.a3f1...7b8c.QPg24ggKk7xKd2t3c5rL9A.1715350800.AAAA...")` |
| Fulfill response (server/operator → plugin) | `SHA-256("{version}.{action}.{intent_id}")` | `SHA-256("1.fulfill.a3f1...7b8c")` |
| Reject response (server/operator → plugin) | `SHA-256("{version}.{action}.{intent_id}")` | `SHA-256("1.reject.a3f1...7b8c")` |
